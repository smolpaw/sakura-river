# Sakura River

Procedural Three.js scene (cherry tree, river, Fuji-style mountain). See README.md for commands, file layout and the engine API.

## Working here

- The owner cares about results, not about knowing the code. Work here is not tracked in GitHub issues. Any language or stack is fine when measurements show it helps.
- This is a demo of what an agent can build, not a product that must run everywhere: WebGPU-only features are fine and Firefox may fail. The WebGL2 fallback stays because the headless look captures need it, but it does not run the WebGPU-only paths, so those are checked in a real browser.
- `docs/performance.md`: what the renderer does for speed, what was rejected and why, open cross-GPU risks. Check it before adding anything that costs GPU time, and add new findings there.

## Conventions

- Everything visual is generated in code — no image or texture assets, no hand-made models. Code includes Blender Python scripts in `tools/` that build models into `src/models/` (and the Ultra tier's detailed `_near` levels into `public/models/`) (owner, 2026-09-30, who has Blender installed and doesn't use it themselves: modelling there is Claude's job); the woods' trees, the gorge's rock walls, the bamboo, the river's boulders, the cherries' trunks, the village's buildings, the shrubs, the riverside's lamps, the stones by the lanes, the heron and the egrets and the walk mode's traveller are built this way (`tools/forest.py`, `tools/cliffs.py`, `tools/bamboo.py`, `tools/rocks.py`, `tools/cherry.py`, `tools/village.py`, `tools/shrubs.py`, `tools/lamps.py`, `tools/wayside.py`, `tools/heron.py`, `tools/human.py`, run by `node tools/blender.mjs`). The cherries' trunks are built from the skeletons `src/tree.js` grows: any change to how the trees grow, where they stand or the ground under them needs `node tools/blender.mjs cherry` (the page warns in the console when the model no longer fits). Check such models under the scene's own lighting (look captures), not only in Blender renders. The village's layout (farmland zones, lanes, building pads) lives in `src/world.js` because the ground's height depends on it; keep the farmland and pads clear of the small cherries (the `CLEAR` list there) or their trunk models stop fitting. Exceptions: sound (owner, 2026-09-27): recordings in `public/audio/`, built by `tools/audio.mjs` and credited in README.md (Sound); and the deer (owner, 2026-09-28, after a code-built kitten was dropped for looking bad): Quaternius models in `src/models/`, built by `tools/models.mjs` and credited in README.md (Models). A new sound or model source needs a licence that allows this and a README credit.
- `three` is pinned to an exact version. The materials are TSL node materials (`src/tsl.js`, `src/materials.js`) that reproduce r170's lighting by subclassing three internals (`PhysicalLightingModel`), `main.js` wraps the private `renderer._getFallback`, and `lods.js` patches `WGSLNodeBuilder.getUniformFromNode` so a material's instanced draws share one pipeline, so a three upgrade can silently break the look or bring back a slow start-up. Check visually and `createMs` after any bump.
- TSL: don't assign three's lighting properties (`diffuseContribution`, `roughness`, …) inside an `If` in a material's setup: on frames the branch is skipped the lighting comes out black. Compute a factor and assign unconditionally.
- TSL: an `Fn` without `setLayout` is inlined, so a `Loop` inside it nested in another `Loop` reuses the variable `i` and breaks silently: name the loops apart (`Loop({ start: 0, end: n, type: 'int', name: 'puff' }, ({ puff }) => …)`).
- The time of day doesn't tick (owner, 2026-10-02). It stays where it is set (four presets, a half-hour slider), and only the time-lapse to a newly picked time moves it, which stays (the owner likes it). A running clock moving the sun, shadows, moon and stars was removed: its shadow-map redraws under a moving sun made shadows flicker, it cost GPU time and added little. Don't propose bringing back a ticking clock.
- `src/ui.js` is page wiring only; scene logic belongs in the engine modules behind `create()`.

## Verifying changes

- Run `pnpm dev` and look at the scene in a browser. There are no automated tests.
- Quick look without a window on the owner's desktop: `node bench/build.mjs look && LOOK_BACKEND=webgl BENCH_HEADLESS=1 node bench/look.mjs look out/look <time,...> [hero|x,y,z:tx,ty,tz ...]` writes PNGs to `bench/out/` (headless WebGPU canvases read back blank, hence WebGL; `QUALITY=medium|low` for the other tiers). Headless WebGPU runs always log `OperationError: Instance dropped in popErrorScope` (about 14 times) as the browser closes, on every build including known-good ones: ignore it, don't bisect it; look for other errors.
- In one `look.mjs` run, the river can show the reflection of the previous capture: a night time after day times, or another view's ground (a pale or green sheet over the water). The reflection renders every other frame and the settle steps don't render. Capture the view or time in its own run before calling the river a regression.
- The engine handle (`window.SakuraRiver.create`'s return value) has debug hooks for headless checks: `setView(pos, target)`, `cineView(u)`, `tick(n, dt)`, `simulate(sec)`, `info()`, `soundInfo()`, `birdInfo()`, `koiInfo()`, `heronInfo()`, `figureInfo()` (the fisherman and the rice planter: where, clip, rows planted), `figureAct(name)` (starts the fisherman's `lift` or the planter's `stretch`), `shootingStar()` (launches one ahead of the camera), `setWalk(on)` (walk mode; resolves once the walker is in the scene), `walkTo(x, z, yaw)` (stand there on the network), `walkInput({ forward, strafe, hurry, yaw, pitch })` (held until changed), `walkInfo(detail)` (where he stands, eye, surface; `detail`: the network), `setCulling(on)` (per-instance view culling of the models); `create(canvas, { manual: true })` disables the RAF loop.
- Walk mode: `node bench/build.mjs walk && LOOK_BACKEND=webgl BENCH_HEADLESS=1 node bench/walk-look.mjs walk out/w 11 [legs]` walks every leg of the network (or the named ones) as the traveller and captures the way, looking down and the orbit view after; it prints per leg whether it got through. Headless, render one frame per browser frame (a `requestAnimationFrame` each) before capturing a skinned mesh (the traveller, the deer): three updates their bones once per browser frame, so the frames of one `tick(n)` call, and the shadow map drawn in them, pose him where the first had him.
- People at work: `node bench/figures-look.mjs look out/f '<json shots>'` waits for their model (fetched after start-up), captures views at times and weathers, can start a figure's second clip and capture again seconds later, and prints their state and mesh counts (shot format at the top of the script).
- Birds: `node bench/birds-look.mjs look out/b '<json shots>'` sets time and weather, simulates and captures the scene or a view following one bird (shot format at the top of the script).
